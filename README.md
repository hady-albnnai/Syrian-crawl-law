# مشروع ميزان — الزاحف القانوني السوري

هذا المستودع هو نواة **طبقة جمع واستخراج البيانات القانونية** لمشروع ميزان. يحتوي حالياً على نموذج أولي لزاحف مهذب، ومستخرج نصوص قانونية، وطبقة SQLite تجريبية.

> المشروع الحالي لا يحتوي بعد على FastAPI أو PostgreSQL/pgvector أو Embeddings أو RAG أو تطبيق Flutter. الخطة الكاملة للانتقال من النموذج الأولي إلى منصة ميزان موثقة في [docs/ROADMAP.md](docs/ROADMAP.md).

## الحالة الحالية

> **الأرقام الحية والجبهات المفتوحة:** راجع [ملف التسليم الموحّد
> (2026-09-23)](HANDOVER_2026-09-23.md) — الرصيد المثبت في قاعدة المالك 1,759
> قراراً و1,871 استشهاداً، وخطة تكثيف الزواحف. والتسليمات السابقة للتأريخ:
> [إقفال ف٢ (2026-09-17)](DELIVERY/CRAWLER-HANDOVER-2026-09-17.md)، وما يلي
> لقطة تاريخية من 2026-09-05 عند التسليم 1.

- `recon.py`: استطلاع بنية المصدر.
- `fetcher.py`: جالب HTTP مهذب (robots فعلي) مع تأخير وإعادة محاولة.
- `extractor_v4.py`: استخراج مواد بهرمية وفقرات ودرجة جودة + سقوط عام مُقيَّم.
- `crawler.py`: زحف قابل للاستئناف (طابور SQLite) — **يكتشف محرك كل صفحة**
  (phpBB/WordPress/عام) ويتعامل مع المصادر المكتشفة، والمصدر أحادي الصفحة
  يُحفظ وثيقة كاملة.
- `discovery.py` + `autopilot.py` + `engines.py`: **اكتشاف وتقييم آلي للمصادر**
  (بذور/بحث/تنقيب المتن/خرائط مواقع). يسجّل الدرجة (0–100) ونوع المحتوى
  والأدلة والأسباب؛ الوضع الافتراضي مقترحات للمراجعة فقط، بلا اعتماد أو زحف.
- `database.py`: مخطط SQLite وهجراته الإضافية + `prune_corpus` لصيانة المتن.
- الحالة الحية (2026-09-05): **54 وثيقة / 3676 مادة / 3784 قطعة** من
  3 مصادر معتمدة (المنتدى + ويكي مصدر + محامة) — اكتُشف اثنانها تلقائياً.
- القياس: Recall@5=1.00 · MRR=1.00 · إسناد 1.00 · رفض آمن 1.00 (12 سؤالاً) —
  `tests/` فيها 96 اختباراً محلياً بلا شبكة.

## التشغيل الموحد (التسليم 1)

```bash
pip install -e ".[dev]"          # التبعيات + أدوات التطوير (+ PySide6 للواجهة)
python -m cli init               # إنشاء الجداول والمجلدات
python -m cli stats              # الأعداد الفعلية من قاعدة البيانات

# الزحف (الخيار الآمن افتراضياً: dry بلا حفظ)
python -m cli crawl --pages 10 --mode dry
python -m cli crawl --pages 30 --mode limited
python -m cli crawl --pages 500 --mode full --yes

# اكتشاف وتقييم المصادر — لا اعتماد ولا زحف تلقائياً
python -m cli autopilot --max-evaluate 12
python -m cli sources list
# بعد مراجعتك فقط:
python -m cli sources approve 1
python -m cli crawl --pages 20 --mode limited

# حزمة ميزان: توليد + بوابة واحدة تُطابق planCsvImport في ميزان
python -m cli export --out export/content_package     # يكتب المانيفست ويطبع البوابة
python -m cli verify export/content_package            # فحص حزمة جاهزة بلا إعادة توليد
python -m cli inject --mizan-root <جذر ميزان> --preview # ماذا سيُحقن (دمج، بلا كتابة)
python -m cli inject --mizan-root <جذر ميزان>           # الحقن الفعلي: دمج فهرس + ملفات + إيصالية

pytest -q                              # محلي فقط — اختبارات الشبكة مستبعدة افتراضياً
```

المُصدِّر يأخذ الوثائق `status='active'` وحدها، و`python -m cli stats` يطبع
التوزيع وسطر «قابلة للتصدير (active)» حتى لا يُحسب الفارق فقداناً. أي تكرار في
اسم الملف يُحلّ بلاحقة `_2` لا بكتابة فوق الملف (قِيس على قاعدة المالك: التكرار
كان يدفن وثائق ويجعل البوابة حمراء «بصمة غير مطابقة»)، والبوابة ترفض الآن أي
`local_path` مكرر لأن ميزان يفصل التكرار على `filePath`. تفصيل العلة والإصلاح:
`DELIVERY/EXPORTER-REPORT.md` §11.

بوابة `export` **خروجها 1** إن أخفقت أي فحص (لا يُبنى على مقياس صحيحي) — وهي
**حمراء على الحزمة الفارغة** أيضاً: قِيس أن «✓ ستُستورد كل الصفوف» كان يُطبع مع
0 صفوف، فصار «الفهرس فيه صفوف تُصدَّر (0)» فحصاً راسباً، ولا يكتب الحقن شيئاً
تحت بوابة حمراء (و`--force` يبقى ممراً مسجَّلًا في الإيصالية). وكل رقم في
`mizan_package_manifest.json` مقروء من الحزمة على القرص لا من القاعدة. تفصيل العقد:
`DELIVERY/PACKAGE-MANIFEST-V2.md`؛ ومواصفة جدول المواد في ميزان (لا تُنفَّذ هنا):
`DELIVERY/MIZAN-LAW-ARTICLES-SPEC.md`. و«الحقن في ميزان» (‏`mizan_injector.py`، وزرّه
في شاشة الحزمة): **دمج** لا تغطية — يبقي صفوف ميزان التي لا يولّدها الزاحف، يرفض
بوابة حمراء، يحفظ نسخة مما يبدّله، يقيس الوجهة بعد الكتابة، ويكتب
`mizan_injection_receipt.json`؛ ولا يلمس قاعدة بيانات ميزان. ما تبقى عند ميزان
(خطّاف جذر + زرّ استيراد + استبدال `filePath`) موثّق في
`DELIVERY/MIZAN-INJECTION-HOOKS.md`.

## واجهة سطح المكتب — أربع شاشات (‏`app/`)

الواجهة لا منطق لها ثانٍ: كل شاشة تقرأ من `app/core_data.py` الذي يقرأ القاعدة
والحزمة **وقت الطلب**، وكل قرار يكتبه تمرّر عبر دالة الـCLI نفسها — فلا مسارين
للحقيقة.

| الشاشة | ما فيها | ما يوازيها في الطرفية |
|---|---|---|
| `01-home` | بدء/إيقاف الزحف، مفتاح «تجريبي — بلا حفظ»، عدّادات الطابور الحيّة | `python -m cli crawl [--mode dry]` |
| `02-sources` | لائحة المصادر المعلّقة/المعتمدة/المرفوضة + اعتماد ورفض جماعي بمعاينة وتأكيد | `python -m cli sources list\|approve\|reject` |
| `03-review` | مراجعة الوثيقة، صورة المتن، وتقارير الدورات: جدول الطابور برابطه وآخر عطل مسجل، وإعادة **للمحدد** بالـid أو للفاشل كله | `python -m cli tasks --status failed` + `python -m cli requeue` |
| `04-package` | حزمة ميزان: البوابة، العدد المُقاس من القرص، و«⇩ حقن في ميزان» | `python -m cli export\|verify\|inject` |

لماذا الشاشة الرابعة وُجدت: «اعتماد المصادر تلقائياً» مطفأ افتراضياً (القرار
للمالك حسب السياسة الموثقة)، فبقيت المصادر المعلّقة تُراكَم بلا أي طريقة لاعتمادها
من الواجهة — الزحف يتوقف عند بوابة صامتة لا يراها من لا يفتح الطرفية.

فحص سريع أن الشاشات الأربع تُبنى فعلاً (يُستعمل أيضاً داخل نسخ PyInstaller،
ويخرج **3** إن فُقدت وحدة عقد أو انكسرت شاشة):

```bash
python -m app.main --smoke --smoke-all
```
السجلات: طرفية + `logs/harvester.log`. لا أسرار في Git (`.env.example`).
