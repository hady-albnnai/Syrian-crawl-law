# تصميم: الزاحف يتعلم يبحث عن مصادره لحاله (لا إضافة يدوية)

**التاريخ:** 2026-09-05
**الحالة:** تصميم للمراجعة — **لا تنفيذ قبل موافقة المالك على هذا المستند**
**الطلب الحرفي:** «بدي تبرمج الزاحف يتعلم يبحث عن مصادرو مو ضيف المصادر انا
عن طريق الإضافة اليدوية» + توضيحات: (1) متابعة الإشارات النصية للقوانين
المذكورة داخل المتن + التعلم من التجارب السابقة، (2) بعد ما يلاقي وثيقة
يقارنها مع القاعدة وينقّح ويختار الأفضل، (3) قائمة فروع قانونية شاملة +
تحليل فجوات، (4) فرز أخير حسب الفرع القانوني.

---

## 0. الوضع الحالي بالضبط (فحص فعلي، لا افتراض)

قبل التصميم، هاي حقيقة الكود اليوم كما هو، بالأرقام:

| الموجود | الملف | الحد الحالي |
|---|---|---|
| بذور يدوية | `discovery.SEED_SOURCES` | **2 مصدر** مكتوبين بالكود حرفياً |
| استعلامات بحث | `autopilot.DEFAULT_QUERIES` | **3 استعلامات ثابتة** مكتوبة بالكود |
| تنقيب المتن | `autopilot.mine_corpus_links` | يقرأ **hyperlinks فعلية** فقط من HTML المخزّن — **لا يقرأ الإشارات النصية** («القانون رقم 10 لعام 2015») |
| فروع قانونية | `config.BRANCH_KEYWORDS` | **7 فروع فقط** (مدني/جزائي/أصول/أحوال شخصية/تجاري/دستوري/إداري) — ناقصة عمل، ضرائب، إدارة عامة، بيئة، إلخ |
| مقارنة بالقاعدة قبل القبول | — | **غير موجود إطلاقاً.** كل وثيقة تُحفظ بمعزل عمّا سبق — لا كشف تكرار موضوعي (نفس القانون من مصدرين)، ولا مقارنة جودة، ولا اختيار "أفضل نسخة" |
| رقم/سنة القانون | `documents.number` / `documents.year` | **الأعمدة موجودة بالمخطط لكن لا شيء يملأها.** كل قانون محفوظ اليوم `number=NULL, year=NULL` |
| التعلّم من التجارب | — | **غير موجود.** كل دورة اكتشاف مستقلة عن سابقتها؛ لا سجل لأي مصدر "نجح تاريخياً" يرفع أولويته، ولا سجل لأي نمط بحث "أنتج نتائج ضعيفة" يُخفَّض |
| تحليل الفجوات | — | **غير موجود.** لا تقرير "عندي X من فرع كذا وناقصني كذا" |

الخلاصة: عندك حالياً "بحث آلي بمدخلات ثابتة"، مش "زاحف يتعلم". التصميم تحت
يحوّل الأربعة قنوات الحالية لحلقة تتغذى من نفسها.

## 1. المبدأ العام: حلقة تتعلم لا قائمة تُنفَّذ

```
                    ┌─────────────────────────────────────┐
                    │        1. توليد المرشحين            │
                    │  (بذور + بحث ديناميكي + إشارات      │
                    │   نصية من المتن + sitemaps + أولوية  │
                    │   من سجل نجاح سابق)                  │
                    └───────────────┬───────────────────────┘
                                    ▼
                    ┌─────────────────────────────────────┐
                    │        2. تقييم مهذب (موجود)         │
                    │  robots → استخراج v4 → legal_score   │
                    └───────────────┬───────────────────────┘
                                    ▼
                    ┌─────────────────────────────────────┐
                    │   3. مطابقة القاعدة (جديد بالكامل)   │
                    │  هل هاد القانون موجود عندي أصلاً؟    │
                    │  (بهوية القانون: نوع+رقم+سنة، لا     │
                    │   العنوان الحرفي) → قرار: جديد /      │
                    │   نسخة أفضل / نسخة أضعف / مكرر مطابق  │
                    └───────────────┬───────────────────────┘
                                    ▼
                    ┌─────────────────────────────────────┐
                    │  4. استخراج الإشارات + توليد مرشحين  │
                    │     جدد من نص الوثيقة نفسها          │
                    │  («المعدل بالمرسوم رقم 32 لعام 2021») │
                    └───────────────┬───────────────────────┘
                                    ▼
                    ┌─────────────────────────────────────┐
                    │   5. تسجيل نتيجة الدورة (تعلّم)      │
                    │  هل هاد المصدر/الاستعلام أنتج شيئاً؟  │
                    │  يرفع/يخفّض أولويته للدورة الجاية     │
                    └───────────────┬───────────────────────┘
                                    ▼
                    ┌─────────────────────────────────────┐
                    │  6. تقرير فجوات + فرز بالفرع          │
                    │  (تشغيل دوري لا كل دورة)              │
                    └─────────────────────────────────────┘
```

كل قطعة تحت مرتبطة بملف/دالة محددة — لا شيء نظري.

## 2. القطعة الأولى: هوية القانون (Law Identity) — أساس كل شيء بعدها

**لازم تُبنى أولاً** لأن القطع 3 و5 و6 كلها تعتمد عليها. بدونها "المقارنة
بالقاعدة" مستحيلة فعلياً (العنوان النصي وحده غير كافٍ: "قانون العقوبات
السوري" و"قانون العقوبات السوري رقم 148 لعام 1949" و"قانون العقوبات" ثلاث
صيغ لنفس القانون).

### 2.1 ما يُستخرج من كل وثيقة (دالة جديدة `law_identity.py`)

من العنوان + أول 500 حرف من النص (حيث تُذكر الديباجة عادة)، عبر تعبير نمطي:

```python
LAW_ID_RE = re.compile(
    r"(القانون|المرسوم التشريعي|المرسوم|القرار|النظام|التعليمات)"
    r"[^\d]{0,15}رقم\s*[/\(]?\s*(\d+)[/\)]?"
    r"[^\d]{0,15}لعام\s*(\d{4})"
)
```

يُخرج: `doc_type` (قانون/مرسوم تشريعي/...)، `law_number` (148)، `law_year`
(1949). هذا **يملأ أعمدة `documents.number` و`documents.year` الفارغة
حالياً فعلياً** — إصلاح لا ميزة إضافية.

### 2.2 مفتاح الهوية (`identity_key`)

```
identity_key = normalize(doc_type) + ":" + law_number + ":" + law_year
# مثال: "قانون:148:1949"
```

عند غياب رقم أو سنة (نص لا يذكرهما — يحصل فعلاً بمصادر ضعيفة الجودة)،
`identity_key = None` والوثيقة تُقيَّم بمطابقة العنوان المطبَّع فقط (احتياطي
أضعف، يُسجَّل صراحة `identity_confidence: "title_only"` بدل الادعاء بيقين
غير موجود).

### 2.3 لماذا هذا القرار تحديداً

بدائل مرفوضة ولماذا:
- **الاعتماد على تشابه نص كامل (fuzzy text diff):** مكلف حسابياً على متن
  كبير، وحساس لفروق تنسيق لا معنى قانونياً (مسافة، ترقيم) — يعطي نتائج
  غير مستقرة.
- **الاعتماد على `source_url` فقط:** هذا موجود أصلاً (`UNIQUE` بالمخطط)
  ولا يحل المشكلة — نفس القانون بمصدرين له رابطان مختلفان تماماً.

هوية (نوع + رقم + سنة) هي المعرّف القانوني الفعلي المستخدم في الجريدة
الرسمية نفسها — لا اختراع، بل استخراج حقل موجود أصلاً في كل نص تشريعي سوري.

## 3. القطعة الثانية: متابعة الإشارات النصية (لا hyperlinks فقط)

### 3.1 الفجوة المحددة

`mine_corpus_links` الحالية (`autopilot.py`) تفحص وسم `<a href>` فقط. نصوص
القوانين نفسها فيها إشارات لقوانين أخرى **كنص عادي بلا رابط**:
- "المعدل بالمرسوم التشريعي رقم 32 لعام 2021"
- "بموجب القانون رقم 10 لعام 2015"
- "الملغى بالقانون رقم 4 لعام 2018"

هذه لا تُلتقط اليوم إطلاقاً.

### 3.2 الحل: `extract_law_references(text) -> list[dict]`

يُستخرج بنفس `LAW_ID_RE` من القطعة 2، مطبَّقاً على **كل** نص مادة (لا
العنوان فقط)، فيعيد قائمة `{doc_type, law_number, law_year, context}`
(السياق = 80 حرفاً حول الإشارة، لتمييز "عدّل" عن "ألغى" عن "استند إلى").

### 3.3 من إشارة نصية إلى مرشح بحث

الإشارة النصية مالها URL — ما منقدر نزحفها مباشرة متل رابط hyperlink.
الحل: تتحول لاستعلام بحث مولَّد آلياً:

```
"{doc_type} رقم {law_number} لعام {law_year} سوريا نص كامل"
# مثال: "المرسوم التشريعي رقم 32 لعام 2021 سوريا نص كامل"
```

هذا الاستعلام يُمرَّر لنفس `DuckDuckGoHtmlProvider`/`BingApiProvider`
الموجودين أصلاً — **لا محرك بحث جديد**، بس مصدر استعلامات ديناميكي بدل
الاستعلامات الثلاثة الثابتة.

### 3.4 قبل الزحف: تحقق أنه غير موجود أصلاً

قبل توليد استعلام بحث لإشارة معيّنة، تُفحص `identity_key` المقابلة لها
بجدول `documents` (القطعة 2). إن كانت موجودة فعلاً ⇒ لا بحث، توفير موارد.
هذا يمنع إعادة البحث عن نفس القانون بكل دورة لمجرد أنه مذكور بعشر وثائق.

## 4. القطعة الثالثة: مطابقة القاعدة قبل القبول (تنقيح واختيار الأفضل)

### 4.1 المشكلة الحالية بدقة

`save_document` (`crawler.py`) يفحص **`doc_id` فقط** (بصمة الرابط
المُطبَّع). يعني: نفس القانون من مصدرين (مثلاً منتدى + ويكي مصدر) لهما
`doc_id` مختلفان تماماً ⇒ **يُحفظان كوثيقتين منفصلتين**، حتى لو كانت إحداهما
أفضل جودة (أوضح تقسيم مواد، أقل ضجيج، أشمل هرمية) من الأخرى.

### 4.2 معيار "الأفضل" — **محدَّد صراحة من المالك**، بترتيب أولوية صارم

المالك حدد معيارين بالأولوية: **(1) المصدر الرسمي أولاً، (2) النص الكامل
ثانياً**. الباقي (تفاصيل التنفيذ) صُمم أدناه بعد بحث عملي في أفضل
الممارسات (انظر §4.2.3 لمصادر البحث). الترتيب الكامل المطبَّق:

```
استخراج identity_key من الوثيقة الجديدة
  │
  ├─ identity_key = None (لا رقم/سنة قابل للاستخراج)
  │    → تحفظ كالمعتاد اليوم (سلوك حالي، بلا تراجع)
  │
  └─ identity_key موجود → بحث بجدول documents عن نفس identity_key
       │
       ├─ لا يوجد مطابق → وثيقة جديدة فعلاً → تُحفظ عادي
       │
       └─ يوجد مطابق (نسخة سابقة بنفس القانون) → مقارنة بترتيب صارم
            (كل معيار يحسم فقط عند تعادل تام بالمعيار السابق):

              1. **رسمية المصدر (domain_tier)** — المعيار الحاسم الأول،
                 كما طلب المالك حرفياً. مصدر أعلى فئة يفوز فوراً بلا
                 النظر لبقية المعايير (§4.2.1 يفصّل الفئات).
              2. **اكتمال النص الكامل (completeness)** — عند تعادل الفئة:
                 نص "كامل" (بلا اقتطاع ملحوظ: `truncated=False` من
                 extractor_v4 + عدد مواد يطابق آخر رقم مادة مذكور بالنص
                 نفسه، انظر §4.2.2) يفوز على نص جزئي/منقول باقتباس.
              3. quality_score من extractor_v4 (تعادل الفئة والاكتمال)
              4. عدد المواد المستخرجة الحقيقية (real_articles)
              5. وجود هرمية مكتشفة (hierarchy_path غير فارغ)
              6. طول النص الكامل (الأطول عند تعادل كل ما سبق)
            │
            ├─ الجديدة أفضل → تحل محل القديمة:
            │     القديمة تُنقل لـ document_versions (لا تُحذف — قاعدة
            │     "النسخ الزمنية لا الاستبدال" في CONSTITUTION.md §الجاهزية
            │     للذكاء الاصطناعي) وتُعلَّم status='superseded'
            │     الجديدة تصير status='active'
            │
            ├─ القديمة أفضل أو متعادلة → الجديدة تُحفظ بـ
            │     status='alternate_source' (لا تُحذف: مصدر بديل موثق
            │     يبقى صالحاً للتدقيق المرجعي — القرار الآمن دستورياً هو
            │     عدم إسقاط بيانات مجموعة بصمت)
            │
            └─ كل قرار (الفائز ولماذا) يُسجَّل في جدول جديد
                  `dedup_decisions` (متى، المتنافسان، المعيار الحاسم،
                  القيم المقارنة) — بلا هذا السجل القرار غير قابل للتدقيق
                  (نفس مبدأ §8.6 من خطة الذكاء الاصطناعي بميزان: "من لا
                  سجل له لا يُصدَّق أنه لم يحدث").
```

#### 4.2.1 فئات رسمية المصدر (`domain_tier`) — بحث فعلي في الحالة السورية

بحثت عن المصادر الرسمية السورية المتاحة فعلياً على الإنترنت اليوم (لا
افتراض) قبل صياغة الفئات:

- **مجلس الشعب السوري (`parliament.gov.sy`)** ينشر فعلاً "مكتبة
  التشريعات السورية" بنص كامل لمواد قوانين مثل القانون المدني — تأكدت من
  ذلك مباشرة (رأيت نص المادة 1 والمادة 937 والمادة 1097 من القانون المدني
  منشورة على `parliament.gov.sy/arabic/index.php?node=5595`).
  → **أعلى فئة رسمية متاحة اليوم لمتن التشريعات نفسها.**
- **الجريدة الرسمية للجمهورية العربية السورية** هي المرجع القانوني الأعلى
  دستورياً (تاريخ نفاذ أي نص من تاريخ نشره فيها)، لكن بحثي أظهر أنها
  **غير متاحة كموقع إلكتروني رسمي معتمد ومستقر اليوم** (تعطّل العمل بها
  منذ التغيير السياسي نهاية 2024، وفق تحليل نُشر على `syria.tv`) — لذلك
  لا تُدرَج اليوم كمصدر تشغيلي فعلي رغم أنها الأعلى نظرياً؛ إن ظهر أرشيف
  رسمي مستقر لها لاحقاً تُرفع لأعلى فئة فوراً.
- **مواقع الوزارات ذات النطاق `gov.sy`** (وزارة العدل `jus.moj.gov.sy`،
  رئاسة الحكومة `pministry.gov.sy`، وزارة الإعلام `momc.gov.sy`، إلخ)
  تنشر مراسيم وقرارات ضمن اختصاصها — رسمية لكن أضيق نطاقاً من مجلس الشعب.
- **ويكي مصدر (`ar.wikisource.org`)** ينشر نصوصاً تشريعية كاملة (تأكدت:
  نص القانون المدني السوري كاملاً موجود) لكنه **مصدر مجتمعي (wiki) لا
  حكومي** — موثوق نسبياً للنص لكنه ليس "رسمياً" بالمعنى الدستوري.
- **منتديات ومدونات قانونية** (مصدر الزحف الأساسي الحالي،
  `law-library.syriaforums.net` وغيره) — نقل ثانوي، جودة متفاوتة، لا
  رسمية إطلاقاً.

بناءً على هذا، فئات `domain_tier` (عدد صحيح، الأصغر = أعلى رسمية،
مبدأ شائع بأنظمة تقييم مصداقية المصادر — يُرتَّب المصدر تصاعدياً بدل نقاط
معقدة، لسهولة التفسير والتدقيق):

| tier | الفئة | أمثلة فعلية | كيف يُكتشف آلياً |
|---|---|---|---|
| 0 | الجريدة الرسمية (إذا/عندما تتوفر إلكترونياً) | — (غير متاح حالياً) | نطاق مدرَج يدوياً بقائمة محصورة جداً عند توفره |
| 1 | مجلس الشعب / رئاسة الجمهورية / رئاسة الحكومة | `parliament.gov.sy`, `pministry.gov.sy` | نطاق ينتهي بـ`gov.sy` **و** مطابق لقائمة محصورة (لا كل `gov.sy` تلقائياً — بعض النطاقات الحكومية خدمية لا تشريعية) |
| 2 | وزارة مختصة بنشر تشريعات ضمن اختصاصها | `moj.gov.sy`, `momc.gov.sy` | نفس آلية tier 1 |
| 3 | مصدر مرجعي مجتمعي موثوق للنص القانوني | `ar.wikisource.org` | قائمة محصورة يدوياً (مصداقية النص لا الجهة) |
| 4 | منتدى/مدونة قانونية عامة (الوضع الافتراضي الحالي) | `law-library.syriaforums.net` | أي مصدر غير مصنَّف بفئة أعلى |

القائمة المحصورة (tiers 0-3) تُخزَّن بـ`config.py` كثابت جديد
`OFFICIAL_DOMAIN_TIERS: dict[str, int]` — **إضافة صريحة يدوية بإشراف
المالك، لا اكتشاف تلقائي للرسمية** (تصنيف "هل هذا الموقع حكومي رسمي
فعلاً" قرار له تبعات دقة عالية، لا يُترك لتخمين آلي؛ نفس مبدأ CONSTITUTION
بعدم الادعاء بيقين غير مقاس). عمود جديد `sources.domain_tier` يُملأ عند
اعتماد كل مصدر (افتراضي 4 لأي مصدر غير مدرَج بالقائمة).

#### 4.2.2 اكتمال النص الكامل (`completeness`) — كيف يُقاس فعلياً لا بالتخمين

"النص الكامل" (المعيار الثاني الذي حدده المالك) يُقاس بثلاث علامات
موضوعية، كلها مبنية على حقول يستخرجها `extractor_v4.py` أصلاً اليوم (لا
حقل جديد يحتاج نموذجاً جديداً):

1. **لا اقتطاع صريح بالنص** — غياب عبارات القص الشائعة بالمصادر الثانوية
   ("...", "اقرأ المزيد", "تتمة", "المصدر:") قرب نهاية النص المستخرَج.
2. **تسلسل أرقام المواد متصل** — إن استُخرجت المواد 1، 2، 3، 7 (بفجوة)
   فهذا مؤشر نص منقوص (أو تجميع مقتطفات لا نص كامل)؛ إن كانت 1..N متصلة
   بلا فجوة فهي إشارة اكتمال قوية. هذا فحص مباشر على قائمة `article_number`
   الموجودة أصلاً من `extractor_v4.extract_articles`.
3. **آخر مادة مذكورة تطابق أعلى رقم مستخرَج** — كثير من النصوص القانونية
   تختم بمادة "أحكام ختامية/نفاذ" برقم معروف مسبقاً إجمالاً (حين يُذكر
   "المادة الأخيرة" أو رقمها صراحة بمكان آخر بالنص) — تحقق تكميلي بسيط.

الثلاثة تُدمَج بعلم منطقي واحد `is_complete: bool` (وليس نسبة مئوية
مركّبة — تبسيطاً وقابلية تفسير، بما يوافق مبدأ الشفافية بالتصميم). يُخزَّن
بعمود جديد `documents.is_complete_text`.

#### 4.2.3 مصادر البحث التي استندت إليها هذه القرارات

- بحث ويب مباشر تحقق من: `parliament.gov.sy` (مكتبة التشريعات، نص فعلي
  للقانون المدني)، حالة الجريدة الرسمية الإلكترونية (تحليل `syria.tv`،
  آذار 2025)، نطاقات وزارية (`moj.gov.sy`, `pministry.gov.sy`,
  `momc.gov.sy`)، ووجود نص كامل بديل على `ar.wikisource.org`.
- مبدأ تصنيف المصادر بفئات ترتيبية بسيطة (tier) بدل نقاط مركّبة معقدة:
  ممارسة شائعة بأدوات تقييم مصداقية النطاقات (المصادر التجارية كـMoz/
  Semrush تستخدم نقاطاً مركّبة معقدة أصلاً لغرض مختلف — تقييم SEO/الروابط
  الخلفية — غير مناسب هنا لأن لا "روابط خلفية" مجدية بمتن قانوني سوري
  محدود؛ التبسيط لفئة رسمية صريحة أنسب وأسهل تدقيقاً).
- مبدأ حسم التكرار بأولوية صارمة (tier أولاً ثم بقية المعايير عند التعادل
  فقط) بدل دمج نقاط مرجّحة: مبني على أدبيات "ربط السجلات" (record
  linkage/entity resolution) القياسية — القواعد الحتمية الصريحة (بدل
  نموذج احتمالي معقّد) هي الخيار الأنسب هنا لأن حجم المتن صغير نسبياً
  والمعيار الحاسم (رسمية المصدر) صريح ومعرَّف يدوياً أصلاً، فلا داعٍ
  لتعقيد إحصائي إضافي.

### 4.3 تعديل مخطط قاعدة البيانات المطلوب (Migration جديدة، إضافة فقط)

```sql
-- documents: أعمدة جديدة (الأعمدة القديمة number/year تُملأ فعلياً بدل الفراغ)
ALTER TABLE documents ADD COLUMN identity_key TEXT;
ALTER TABLE documents ADD COLUMN identity_confidence TEXT;  -- 'number_year' | 'title_only'
ALTER TABLE documents ADD COLUMN is_complete_text INTEGER;  -- 0/1، معيار الاكتمال §4.2.2
ALTER TABLE documents ADD COLUMN source_domain_tier INTEGER;  -- منسوخ من sources.domain_tier
                                                               -- وقت الحفظ، لتسريع المقارنة
                                                               -- بلا JOIN بكل عملية تكرار
CREATE INDEX idx_docs_identity ON documents(identity_key);

-- sources: فئة الرسمية (المعيار الحاسم الأول بالمقارنة، §4.2.1)
ALTER TABLE sources ADD COLUMN domain_tier INTEGER DEFAULT 4;

-- نسخ الوثائق المستبدلة (القاعدة الدستورية: نسخ لا استبدال)
CREATE TABLE document_versions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    original_doc_id INTEGER,      -- ربط بالوثيقة الحالية (الفائزة)
    doc_id TEXT, title TEXT, source_url TEXT,
    clean_content TEXT, quality_score REAL,
    superseded_at TEXT, superseded_reason TEXT,
    FOREIGN KEY (original_doc_id) REFERENCES documents(id)
);

-- قرارات تنقيح مسجلة للتدقيق
CREATE TABLE dedup_decisions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    identity_key TEXT,
    winner_doc_id INTEGER, loser_doc_id INTEGER,
    decisive_criterion TEXT,     -- 'quality_score' | 'article_count' | ...
    winner_value REAL, loser_value REAL,
    decided_at TEXT
);
```

## 5. القطعة الرابعة: التعلّم من التجارب السابقة

### 5.1 ما "يتعلمه" الزاحف بالضبط (تعريف عملي، لا تسويقي)

- **مصدر أثبت نجاحه** (مرة بعد مرة وصلنا منه قانون فريد جديد، `identity_key`
  جديد) → أولوية أعلى بدورة الاكتشاف الجاية (يُزار أولاً، أعمق — عدد صفحات
  أكبر من الافتراضي).
- **مصدر أثبت فشله المتكرر** (3 دورات متتالية بلا أي `identity_key` جديد
  منه، أو `verdict=rejected` متكرر) → يُنقل لحالة `status='exhausted'`
  (ليس `rejected` — الفرق: استُنفد لا أنه سيئ، قد يُعاد فحصه لاحقاً يدوياً)
  ولا يُعاد تقييمه تلقائياً كل دورة (توفير طلبات شبكة).
- **نمط استعلام بحث أنتج مرشحين مقبولين تاريخياً** (بفروع قانونية محددة)
  → يُعاد استخدامه لاستعلامات فرعية مشابهة عند اكتشاف فجوة بنفس الفرع
  (ربط مباشر بالقطعة السادسة: تحليل الفجوات يغذّي توليد الاستعلامات).

### 5.2 التنفيذ: جدول `source_performance` (إضافة، لا تعديل جدول قائم)

```sql
CREATE TABLE source_performance (
    source_key TEXT PRIMARY KEY,   -- نفس مفتاح sources.source_key
    runs_count INTEGER DEFAULT 0,
    new_identities_total INTEGER DEFAULT 0,  -- إجمالي قوانين فريدة جديدة عبر كل الدورات
    last_run_new_identities INTEGER DEFAULT 0,  -- آخر دورة فقط (لكشف النضوب)
    consecutive_empty_runs INTEGER DEFAULT 0,
    last_evaluated_at TEXT,
    learned_status TEXT DEFAULT 'active'  -- active | exhausted
);
```

يُحدَّث بعد كل دورة `run_discovery`/`start_crawling`: مقارنة عدد
`identity_key` الفريدة الجديدة من هذا المصدر بالدورة الحالية مقابل ما
سبق. **بلا "تعلّم آلي" (ML) حقيقي — هذا عدّاد وقرار عتبي (threshold) بسيط
وشفاف بالكامل، قابل للتفسير سطراً سطراً.** هذا قرار مقصود: أي شيء أعقد
(نموذج تصنيف، تعلم معزز) يكسر مبدأ "لا رقم بلا قياس" و"لا صندوق أسود" في
دستوركم — ويصعب تبرير قراره أمام مستخدم يريد يعرف ليش مصدر معيّن أُهمل.

## 6. القطعة الخامسة: قائمة الفروع القانونية الشاملة

### 6.1 التوسعة المقترحة على `config.BRANCH_KEYWORDS` (7 فروع حالياً)

بحثت بمستودع **ميزان نفسه** (قراءة فقط، `MASTER_PLAN_AI_INTEGRATION.md`)
عن قرارات تصنيف قانونية موثّقة مسبقاً لتفادي التعارض بين الزاحف والتطبيق
المستهلك. وجدت قرارين صريحين مثبَّتين هناك («الملاحظات القانونية المؤكدة»):

- **«العقارية فرع من المدنية (ليست تبويب مستقل)»**
- **«العمالية تتبع البداية المدنية (ليست تبويب مستقل)»**

بناءً عليه، لا أستحدث `real_estate_law` ولا `labor_law` كفرعين مستقلين —
هذا كان سيخلق عدم اتساق مباشر مع تصنيف ميزان القائم فعلاً. بدلاً من ذلك:
كلمات العقارية والعمالية تُضاف كـ**كلمات مفتاحية إضافية داخل `civil_law`**
الموجود أصلاً (توسعة لا فرع جديد)، فيما تبقى الفروع الأخرى (غير المتصادمة
مع تصنيف ميزان) مستقلة كما هو معتاد بمصادر التصنيف القانوني العام:

| فرع | الحالة | كلمات مفتاحية إضافية مقترحة |
|---|---|---|
| `civil_law` (موجود) | **يتوسع** ليشمل العقاري والعمالي (محاذاة صريحة مع ميزان) | + عقار، تسجيل عقاري، طابو، إفراز؛ + عامل، عمل، أجر، إصابة عمل، نقابة عمالية، تأمينات اجتماعية |
| `tax_law` (جديد) | فرع مستقل — لا مقابل له بتصنيف ميزان الحالي أصلاً (ميزان لا يغطي الضرائب كتبويب دعاوى) | ضريبة، رسم، جمارك، دخل، قيمة مضافة |
| `banking_finance` (جديد) | فرع مستقل | مصرف، بنك، صرف، نقد، تمويل، مصرف مركزي |
| `intellectual_property` (جديد) | فرع مستقل | براءة اختراع، علامة تجارية، حقوق مؤلف |
| `environment_law` (جديد) | فرع مستقل | بيئة، تلوث، موارد طبيعية |
| `investment_law` (جديد) | فرع مستقل | استثمار، هيئة الاستثمار، مشروع استثماري |
| `international_private` (جديد) | فرع مستقل | تنازع قوانين، تحكيم دولي، جنسية |
| `military_judiciary` (جديد) | فرع مستقل | محكمة عسكرية، قانون العقوبات العسكري |

ملاحظة تصميمية مهمة: تصنيف **الزاحف** (`BRANCH_KEYWORDS`) وتصنيف **ميزان**
(تبويبات الدعاوى) لهما غرضان مختلفان فعلياً — الزاحف يصنّف **نصوصاً
تشريعية** (قد تغطي فروعاً لا دعاوى مقابلة لها، كالضرائب أو الاستثمار)،
بينما ميزان يصنّف **ملفات قضايا مرفوعة أمام محاكم**. لذلك التطابق الكامل
غير مطلوب ولا منطقي — المطلوب فقط **عدم التعارض** في النقاط المشتركة
(المدني/العقاري/العمالي)، وهذا محقَّق أعلاه. لا حاجة لتعديل ميزان (ممنوع
أصلاً) ولا لانتظار موافقته على فروع لا تخصه.

بعد اعتماد هذا، تُدمج التوسعة بـ `config.BRANCH_KEYWORDS` (لا ملف جديد —
نفس البنية القائمة) وتُستخدم فوراً في: `detect_branch` (تصنيف الوثائق
الموجود أصلاً) + توليد استعلامات بحث لكل فرع (القطعة القادمة).

## 7. القطعة السادسة: تحليل الفجوات + الفرز بالفرع

### 7.1 تقرير الفجوات (أمر جديد `cli gaps`)

```
SELECT branch, COUNT(*) as docs, SUM(article_count) as articles
FROM documents JOIN (عدد المواد لكل وثيقة) GROUP BY branch
```

يُقارَن بحد أدنى متوقَّع لكل فرع يُحسب **آلياً** لا يدوياً (تفصيل القرار
والصيغة في §9) — قابل للاستبدال لاحقاً بتقدير قانوني صريح عبر
`config.EXPECTED_MIN_OVERRIDE` إن رغبت بذلك. الفرع الذي عدد وثائقه الفعلي
أقل من الحد المحسوب ⇒ "فجوة" تظهر بالتقرير + استعلامات بحث مولَّدة
تلقائياً لذلك الفرع تحديداً (تغذي القطعة الأولى بالدورة الجاية).

### 7.2 الفرز بالفرع (بعد كل دورة زحف)

موجود جزئياً (`detect_branch` يُستدعى بـ`_handle_topic` أصلاً) — الإضافة:
تقرير ختامي لكل دورة يعرض توزيع الوثائق/المواد المكتسبة الجديدة بهذه
الدورة **حسب الفرع**، لا رقم إجمالي مبهم فقط. يُضاف لتقرير `crawl_runs`
الموجود (عمود جديد `branch_breakdown_json`)، لا جدول جديد.

## 9. قرارات صُمِّمت بالكامل (بلا أسئلة معلّقة) — بحسب توجيه المالك

المالك حسم معيار الأفضلية صراحة (رسمية المصدر أولاً، النص الكامل ثانياً
— مطبَّق بالكامل في §4.2) وفوّض تصميم الباقي بعد بحث فعلي في أفضل
الممارسات. لا أسئلة معلّقة تمنع البدء بالكود؛ القرارات المتبقية موثّقة
هنا صراحة (قابلة للتعديل لاحقاً بلا تعقيد لأنها كلها إعدادات صريحة
بـ`config.py`، لا منطق متشعب):

- **قائمة الفروع (القطعة 6)**: محسومة بمحاذاة صريحة مع تصنيف ميزان
  الموثَّق فعلاً (العقاري والعمالي يتبعان المدني، لا فرعان مستقلان) —
  تفاصيل كاملة في §6.1، مبنية على قراءة `MASTER_PLAN_AI_INTEGRATION.md`
  بمستودع ميزان (قراءة فقط) لا تخمين.
- **الأرقام المرجعية للفجوات (`EXPECTED_MIN_PER_BRANCH`, القطعة 7)**:
  تُحسب **آلياً لا يدوياً** بدل رقم ثابت مُخمَّن: لكل فرع، الحد الأدنى
  المتوقع = متوسط عدد الوثائق بالفروع الثلاثة الأعلى تغطية حالياً بجدول
  `documents` **مضروباً بـ 0.3** (أي: "لو غطّينا هذا الفرع بثلث ما
  غطينا به أنجح فرع، ما زال ناقصاً"). هذا رقم نسبي متجدد تلقائياً مع نمو
  القاعدة (لا يحتاج تحديثاً يدوياً كل فترة)، ويُستبدل بسهولة لاحقاً بقرار
  قانوني صريح متى ما توفر (مثلاً: تقدير فعلي لعدد التشريعات السورية
  السارية بكل فرع من مصدر موثوق) — التصميم يسمح بذلك عبر ثابت واحد قابل
  للكتابة فوقه بـ`config.EXPECTED_MIN_OVERRIDE: dict[str, int]`، فارغ
  افتراضياً.
- **نطاق "استنفاد" مصدر (القطعة 5)**: أُبقي على **3 دورات فارغة متتالية**
  كعتبة ابتدائية — هذا رقم شائع كخط أساس محافظ بأنظمة "توقف عند الفشل
  المتكرر" (retry/backoff patterns): يكفي لتفادي حكم متسرع على مصدر بعد
  فشل عرضي واحد (شبكة، صيانة مؤقتة)، بينما لا يهدر موارد زحف كثيرة على
  مصدر ثبت نضوبه فعلاً. **قابل للتعديل بثابت واحد** إن ظهر لاحقاً أنه غير
  مناسب بعد تشغيل فعلي.
