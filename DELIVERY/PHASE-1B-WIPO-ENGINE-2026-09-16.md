# تقرير ف١-ب — مصدر ويبو ليكس: أول إسناد رسمي كامل (قانون العقوبات)

**التاريخ:** 2026-09-16 — **المدى:** ف١-ب من ترتيب الفتح المعتمد بتقرير
ف٠ §1 (قرار المالك «موافق ع اقتراحاتك»).

## 1. البوابة المقابلة

بوابة ف١ بالميثاق: «قانون كامل بإسناد جريدة/مصدر معتمد + سلسلة تعديل +
حالة قانونية، محروس باختبارات بنتيجة تشغيل». بهذه الدفعة: **قانون
العقوبات (المرسوم التشريعي 148/1949) — 775 مادة — بإسناد إيداع رسمي
دولي (ويبو ليكس، تير 2)**، والسلسلة تكتمل عند المالك آلياً: قاعدته تحوي
3 وثائق تعدّل هذا الصك تحديداً (قِيست `--list` على جهازه)، فحالته
تصبح «معدَّل» بسلسلة فور دخوله.

## 2. ما بُني

| المكوّن | الملف | الوصف |
|---|---|---|
| مصدر ويبو | `wipo_source.py` | صفحة التفاصيل ← استخراج رابط الـPDF الموقّع من الـiframe (فك كيانات HTML قياسياً) ← جلبه بأدب كامل (robots + تأخير fetcher + ترويسة Referer) ← استخراج PyMuPDF ← تطبيع ← HTML مصنّع بنفس بنية أسطر المصدر ← **نفس بوابات الأنبوب بلا مسار خاص** |
| خطّاف الدورة | `crawler.py` | مهام صفحات تفاصيل ويبو تُحوَّل قبل المعالجة؛ فشل التحويل = فشل مهمة نظيف |
| هوية بصيغة الإسناد المائلة | `law_identity.py` | «رقم 148/1949» (صيغة ويبو) بجانب «رقم 17 لعام 2010» — بمجموعات مسماة |
| تير الإسناد | `config.py` | `wipo.int: 2` موثق السبب (إيداع رسمي دولي) |
| بذر | `official_seed.seed_wipo` + `WIPO_SEED_LAWS` | العقوبات أولاً — القائمة تتوسع بف٢ بفهرسة الدولة |
| إصلاح قصّ المتن | `crawler.py` + `MAX_CLEAN_CONTENT_CHARS` | كان 15000 حرفاً ضمنياً — قصّ العقوبات إلى 8٪؛ الآن 2M موثقاً |
| تبعية | `pyproject.toml` | `pymupdf` + إكمال py-modules الناقصة تاريخياً |

## 3. أخطاء حقيقية اكتُشفت وأُصلحت بالقياس (سجل التعلم)

1. **كيانات HTML بالرابط الموقّع** (`&#x3D;`): الرابط يُرسل مكسوراً
   فيرفضه CloudFront بـ403. اكتُشف بالزحف الحي فقط — الاختبارات المحقونة
   لا تمر من الشبكة فلم تمسكه (لهذا أُضيف اختبار صريح للكيانات).
   الإصلاح: `html.unescape` قياسي.
2. **انعكاس خانات الأرقام بصرياً**: تسلسل المواد 166-170 يظهر خاماً
   661/761/861/961/071 — كل سلسلة أرقام متعددة الخزانات مخزنة معكوسة؛
   تُقلب خانةً خانة. الدليل: التسلسل يستقيم بعد القلب.
3. **نمط ضجيج المنتديات يبتلع البلوك المدموج**: `-{10,}.*?$` مصمم لمسح
   سطر توقيع؛ لما دمجت أسطر الـPDF بفقرات طويلة صار أول خط شرطات زخرفي
   يمسح كل ما بعده بالسطر (792 مطابقة ← 133!). الحل الهيكلي: كل سطر
   مصدر = عنصر مستقل — بنية الأسطر محفوظة فيبقى سلوك الأنبوب كما صُمم.
4. **ترويسة الصفحة وأرقامها**: ترويسة (عنوان التشريع) ورقم الصفحة
   يتكرران بكل صفحة — يُحذفان؛ و«المادة» المتبوعة بسطر أرقام: أولها
   رقم المادة والباقي صفحات.
5. **قصّ clean_content عند 15000** (خلل قديم سابق للمصادر الرسمية):
   نص 195k حُفظ 15k. الإصلاح موثق أعلاه.
6. مكتبة PDF بالقياس: **PyMuPDF 810 أنماط مادة مقابل 24 لـpypdf** —
   القرار بلا جدال.

## 6. على جهاز المالك (لإقفال بوابة ف١ كاملة)

```
git pull
python cli.py tasks --contains wipo
python cli.py requeue --status blocked,failed,needs_review,running --contains wipo
python cli.py crawl --mode limited --pages 3
python cli.py law-status --rebuild --list
```

سطر `tasks` يكشف حالة مهمة ويبو وآخر عطلها (التشخيص قبل العلاج)،
وسطر `requeue` يعيدها أياً كانت حالتها الميتة. المتوقع بعد الـcrawl:
دخول نسخة ويبو (775 مادة، تير 2) — ونسخة المنتدى للعقوبات التي كشفت
هويتها صيغةُ السنة المائلة تُؤرشف تلقائياً بآلية dedup الموجودة
(الأفضل يفوز، نسخ لا حذف). وبالسطر الأخير: `تعديل ×3 ← المرسوم
التشريعي:148:1949 (✓ موجود بالمتن)` وحالته **معدَّل** — بوابة ف١
بالنص الحرفي للميثاق.

### ٦-أ. ملاحظة نشر — أول تشغيل عند المالك كشف فجوة عتاد (أُصلحت)

أول تشغيل حقيقي عند المالك (2026-09-16) كشف: استيراد pymupdf كسول
بـ`pdf_to_text`، فمحاولة زحف قبل اكتمال `pip install` تصل لحد التحويل
ثم تفشل المهمة — والبذر يتخطى الرابط الموجود **أياً كانت حالته**
والطابور لا يلتقط الفاشلة ثانية، فتبقى المهمة ميتة بلا سبيل للعودة
(العَرض: «بذر ويبو: skipped 1» + «الطابور فارغ»). الإصلاح: أمر
`requeue` (منطقه `crawl_queue.requeue_by` — يعيد بالحالات المطلوبة
مع تصفير عدّاد المحاولات، ورشح `--contains`، ولا يمسّ needs_review
إلا بطلب صريح) + 3 اختبارات. عتاد قياسي لطابور دائم سيلزم ف٢ كثيراً.

### ٦-ب. جولة المتابعة — التشخيص اكتمل وثلاث أراضٍ أُزيلت (2026-09-16 مساءً)

تشغيل المالك للمرة الثانية حسم الحقيقة: **السلسلة تعمل فعلاً** —
`تعديل ×3 ← 148:1949 (✓ موجود بالمتن)` وحالة `معدَّل: 1`، لأن نسخة
منتدى لقانون العقوبات كانت مخبأة بمتنه بلا هوية (صيغة «148/1949»
المائلة كانت خارج النمط القديم) فكشفها `--reidentify` بالصيغة الجديدة
(gained 2). ومهمة ويبو ليست failed (requeue لم يجدها) — القصة
المكتملة من الكود: محاولتها الأولى ماتت قبل بلوغ الـPDF (فشل جلب
صفحة التفاصيل صُنّف حجباً ← هي على الأرجح الـblocked الوحيدة بالطابور).
وفي أثناء التشخيص أُزيلت ثلاث أراضٍ:

1. **قنبلة SystemExit بpdf_to_text**: غياب المكتبة كان يرفع SystemExit
   (BaseException لا يلتقطه except Exception) — يقتل الدورة فوراً
   ويترك المهمة عالقة running أبداً. صار RuntimeError محتوى بـ
   as_pipeline_result: فشل مهمة نظيف برمز `wipo_pdf_module_missing`.
2. **لا إنقاذ للمهام العالقة**: أي دورة تنكسر (انقطاع/Ctrl+C/استثناء)
   تترك مهمتها running ميتة — claim_next لا يراها. أُضيف
   `requeue_stale_running` ببداية كل دورة (مهلة 10 دقائق تحمي دورية
   الويب المتوازيتين من سرقة مهمتها النشطة).
3. **عمى الطابور**: لا سبيل لرؤية حالة مهمة معينة — هذه الجولة كلها
   حدثت لغيابها. أُضيف أمر `tasks` (رشح بالحالة والرابط، مع المحاولات
   وآخر عطل).
